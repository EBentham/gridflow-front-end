## Executive summary

The site is honest in intent but reads AI-generated in three compounding ways, and a 30-second recruiter scan hits all of them. **First, the voice is templated to the point of monoculture:** every homepage and dataset heading is an uppercase eyebrow stacked over a short italic-final-word fragment ending in a full stop (`index.html` L323/493/555/669/754/817; `fuelhh.html:234` "What this dataset is.", `day_ahead_prices.html:247` verbatim the same), the middot is the only structural separator anywhere on the site (`fuelhh.html` has 18; `index.html:819` "Quantitative Developer / London / UK"), and the positioning tagline is stamped three times verbatim (`index.html` L5/L7/L319) — this rhythmic sameness is the single biggest driver of the "looks a bit AI-generated" complaint (`design-01`, `design-02`, `home-01`). **Second, the "very wide figures/tables" complaint has two distinct mechanisms that must both be fixed, not one:** on mobile/narrow viewports a hardcoded `<meta viewport content="width=1280">` on 161 of 162 dataset pages pins the layout viewport so the responsive breakpoints never fire and the whole page scales down (`a11y-01`, `elexon-01`, `entsoe-01` — also a WCAG 1.4.10 reflow failure); on **desktop** the viewport tag is ignored and the real cause is the absence of any shared text-measure token — prose is hand-clamped to ~680px inline while `.chart`, `.schema-table`, `.data-table` and code blocks fill the ~800-930px main column, so figures render visibly wider than the text beside them (`theme-01`, `sources-03`, `elexon-02`, `gas-weather-01` states the desktop-ignores-viewport point verbatim). A third, separate symptom is charts letterboxing into vertical whitespace from a fixed `height` attribute (`charts-02`) — distinct from the horizontal complaint. **Third, the site quietly overstates what is built:** four of five homepage models are vaporware under a "1 shipping / 4 planned" chip with internal phase codes (`home-02`), the flagship model page presents invented metrics and a "Source on GitHub" link that 404s because the repo is private (`model-01`), the architecture repo-map lists `gold/` files that do not exist (`arch-01`), an advertised `from gridflow import GridflowClient` import raises ImportError (`arch-02`), and 2,042 internal `cite`/`src-cite` spans leak class paths and `schemas/*.py Lnn` line numbers as visible body text across 129 pages (`honesty-01`, `gas-weather-04`). Layered on top are roadmap tells the v3 brief explicitly bans — "Static snapshot / live wiring planned" on 161 charts (`honesty-04`, `entsoe-03`, `gas-weather-02`), stale `2026-05-xx` "verified on" stamps and example URLs on 162 pages (`honesty-03`), and a fake-dashboard kit (dead `24h/7d/30d` toggles, "VOLUME / LAST 7 DAYS" sparklines, non-functional Sort/Export chips) that violates the no-dashboard anti-goal (`design-03`, `sources-02`, `theme-05`). The through-line for the revamp: **the work underneath is real and deep, but the surface advertises unfinished plumbing and machine-stamped cadence.** The highest-leverage move is that the 37 mechanical findings collapse into roughly 6-8 deterministic deliverables (one viewport swap, one example-tab facade swap, one honesty strip, a handful of `theme.css`/`site.js` edits) that clear the formatting and honesty debt across all 162 pages at once — which frees the creative budget for the ~19 per-page rewrites that actually buy domain credibility on the recruiter path.

## Recommended revamp direction

A concrete brief for the **2-3 Claude Design directions** to explore on the exemplar (homepage + `system_prices.html`) per D-V3-1/D-V3-5. The user picks one to scale.

### Editorial north star

A recruiter spends 30 seconds and concludes *"this person genuinely knows UK/EU energy market data."* Domain depth over polish. The current build advertises plumbing and unfinished plans; the revamp should advertise **judgement about the data** — what each dataset means in the market, why the medallion design is right, what the gotchas are. Quiet, confident, finished. Anthropic-inspired editorial restraint, not SaaS.

### KEEP (these are working and on-brand)

- The **cream + forest-green palette** and the **Fraunces / Inter / JetBrains Mono** typeface stack (D-V3-1 locks the editorial spirit). The color *tokens* are mostly fine; only the three faint ones fail contrast.
- The **single shared `theme.css` + runtime chrome injection via `site.js` data-* contract** + **seeded inline-SVG charts** architecture. It is coherent and Python-first; do not adopt a Node/Go SSG (explicit anti-goal).
- The **dataset-page anatomy** (hero -> metadata grid -> stats strip -> sticky sidebar -> overview -> snapshot chart -> schema -> sample -> API tabs -> caveats -> related). The *skeleton* is right; the problem is width discipline, voice, and honesty within it.
- The **vault -> site build direction** and the **DuckDB SQL** code tab (it stays accurate — gridflow-models wraps the same `silver_<slug>` views).

### CHANGE (the surface-level AI-tells)

- **Voice / typography rhythm.** Break the heading monoculture (`home-01`, `design-01`) and the middot monoculture (`design-02`). The chosen direction should demonstrate >=3 heading registers and >=2 separator treatments on the exemplar so the user can feel the difference from the current one-template stamp.
- **Honesty.** No roadmap framing, no "live wiring planned", no stage chips, no version strings, no internal class paths, no invented ADRs, no metrics-as-fact for unbuilt models, no fake-live sparklines or dead dashboard toggles. The exemplar must read as *finished*.
- **Code examples.** Show the gridflow-models facade as the primary Python path: `data.elexon.query("system_prices", start, end)` / `data.elexon.describe("system_prices")` — framed as a **local data-access layer**, returning **pandas**, with **no pip/PyPI/availability claims** (it is local-only v0.1.0 per D-V3-3). DuckDB SQL stays as the second tab.

### Typography / color / spacing moves

- **Type scale:** replace the ~25 ad-hoc font sizes (`theme-04`) with a compact modular scale exposed as `--text-*` / `--display-*` tokens. A tighter ramp reads as designed.
- **Contrast:** darken `--ink-faint` (2.28:1) to >=4.5:1 and sweep `--ink-ghost`/`--accent-soft` text uses (`a11y-02`, `a11y-04`). This also removes the washed-out "AI greige" feel.
- **Tokens over literals:** promote the stray hex (`#c45a3a` warn, the dark code/table palette) to tokens (`theme-03`) so the system looks intentional.
- **Separators & whitespace:** fewer middots, more line breaks and small-caps metadata labels; let vertical rhythm carry hierarchy instead of one overloaded inline glyph.

### The dataset-page layout fix for wide figures (both mechanisms)

This is the user's most concrete complaint and the exemplar must visibly solve it. There are **two independent causes — fix both**:

1. **Mechanism A — mobile (the page is pinned).** `<meta viewport content="width=1280">` on 161 pages stops the responsive breakpoints from firing, so narrow viewports render a scaled-down 1280px canvas (`a11y-01`, `elexon-01`, `entsoe-01`; also WCAG 1.4.10). Fix: swap to `width=device-width, initial-scale=1` (already correct on `system_prices.html:6`).
2. **Mechanism B — desktop (no shared measure).** Desktop browsers ignore the viewport tag; the real cause is that prose is hand-clamped to ~680px while `.chart`, `.schema-table`, `.data-table` and code blocks fill the ~800-930px main column (`theme-01`, `sources-03`, `elexon-02`, `gas-weather-01`). Fix: add a single `--measure` (~700px) token and clamp **every** content block — prose, charts, tables, code, stats-strip, the API `1fr 1fr` grid — to the same right edge; re-author chart `data-opts` width from 900 to that measure so SVG geometry matches its box; wrap genuinely wide sample tables (e.g. `boal.html` 14-col) in a measure-clamped horizontal-scroll container rather than letting them set page width.
3. **Separate, also fix:** charts letterbox into vertical whitespace on narrow columns from a fixed `height` attribute — add `[data-chart] svg { height: auto; }` (`charts-02`). This is vertical, not the horizontal complaint, but it is part of "figures look off."

The exemplar should be rendered at desktop **and** ~380px so the user can confirm both mechanisms are resolved: text and figures share one measure on desktop, and the page reflows cleanly (no horizontal scroll, no zoom-out) on mobile.
