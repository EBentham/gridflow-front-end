elexon/fuelhh

Generation by fuel type

FUELHH, Half-hourly Generation Outturn by Fuel Type

Half-hourly GB generation outturn in MW, one value per settlement period for each Elexon fuel-type code.

Grain
One row per settlement period and fuel-type code
Cadence
30 minutes
History
1 Sep 2021 to 26 Sep 2026 in local silver; 7 to 9 Sep 2026 are missing
Publication lag
At the period end, 30 min after its start, on 99.82% of rows; the longest is 271 min
Units
MW; the interconnector codes and PS are signed
Rows
1,682,517; 17 to 20 per half-hour
Silver table
silver_elexon_fuelhh

Workbench call

data.elexon.query(
    "fuelhh",
    "2026-09-20", "2026-09-26")

What it is

For every half-hour settlement period, Elexon publishes GB generation outturn by fuel type. Gridflow keeps one row per period and fuel-type code, upper case as sent: 20 codes in a recent half-hour, ten of them interconnectors. Interconnector and pumped-storage values are signed. There is no solar code.

How it’s used

  • Wind and gas outturn as features for residual-demand and price models.
  • Actuals to score a wind generation forecast against.
  • Tracking the fuel mix and interconnector flows over a week or a year.

Caveats

  • There is no solar code. Solar outturn is not in this dataset; it has to come from another one.
  • Eleven codes are signed: the ten interconnector codes, where positive is import to GB, and PS. Negatives are routine: INTIRL is negative in 70.3% of all half-hours, PS in 54.7%.
  • The code set changes over time. INTELEC starts on 14 Sep 2021, INTVKL on 12 Jul 2023 and INTGRNL on 19 Mar 2024, so a half-hour holds 17 to 20 rows.

Schema

Pydantic class ElexonFuelHH in gridflow/schemas/elexon.py. Transformer version 2.0.0.

ColumnTypeMeaning
settlement_dateDateGB settlement date, derived from the vendor start time since v2.0.0
settlement_periodInt32Half-hour within the date, 1 to 50 (46 or 50 on clock-change days)
timestamp_utcDatetime(us, UTC)Start of the half-hour, UTC (vendor startTime)

lineage4 columnsevent_time, available_at, source_run_id, dataset_version. Added by the silver layer, not the Pydantic class; query() and tail() drop them.

How to get it

Workbench

[1]:
from gridflow_models import setup_notebook
data, models, common = setup_notebook()
[2]:
data.elexon.query("fuelhh", "2026-09-20", "2026-09-26")

Reads silver_elexon_fuelhh and filters settlement_date inclusively: 6,720 rows for this range. Returns a pandas DataFrame. query("fuel_generation", ...) is an alias of the same table.

Vendor endpoint

GET https://data.elexon.co.uk/bmrs/api/v1/datasets/FUELHH
    ?publishDateTimeFrom=<UTC Z>
    &publishDateTimeTo=<UTC Z>
    &page=<n>

Command line

gridflow ingest elexon fuelhh --start 2026-09-20 --end 2026-09-26   # bronze only
gridflow pipeline elexon fuelhh --start 2026-09-20 --end 2026-09-26   # bronze -> silver
