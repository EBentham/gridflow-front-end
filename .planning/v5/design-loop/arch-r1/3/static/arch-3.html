How gridflow is built

Raw API responses land in bronze, cleaned and typed tables settle in silver, and cross-source joins and derived columns sit in gold; one embedded DuckDB file reads silver and gold.

gridflow has no scheduler, no server, no cloud and no live feed: every run is a gridflow command someone starts, and vendor data arrives only when one runs.

The whole system, in one section

The sources stand above ground; gridflow’s layers lie below, with the readers at the foot. The index names each part and links to its file on GitHub.

Discs 1 to 7 mark the stops of the row followed below.

  • gie_alsi GIE ALSI LNG

    European LNG terminal data at country level.

  • gie_agsi GIE AGSI+ gas storage

    European gas storage levels, plus storage unavailability and news.

  • entsog ENTSO-G Transparency Platform

    European gas flows, nominations, capacity, tariffs and gas quality.

  • entsoe ENTSO-E Transparency Platform

    European day-ahead prices, load, generation, cross-border flows, outages and balancing.

  • open_meteo Open-Meteo weather API

    Historical and forecast weather for demand, wind and solar: temperature, wind speed, radiation.

  • neso_data_portal NESO Data Portal (CKAN API)

    Daily wind availability, historic generation mix, embedded wind and solar forecasts.

  • neso NESO Carbon Intensity API

    GB carbon intensity, national and regional, and the generation mix.

  • elexon Elexon Insights API (BMRS)

    GB system prices, generation by fuel, demand, market index prices and REMIT notices.

  • Async requests, capped and retried

    One async httpx client per source; a semaphore caps requests in flight; tenacity retries with jittered backoff.

    connectors/base.py, utils/retry.py

  • Raw bytes plus a sidecar

    Each response is stored byte for byte with a .meta.json sidecar; both land by temp file and atomic rename.

    bronze/writer.py

  • Bronze: raw responses by date

    bronze/{source}/{dataset}/{YYYY}/{MM}/{DD}/raw_{fetched_at}_{hash8}.json, one file per response page.

    bronze/writer.py

  • Typed transformers stamp every row

    One Polars transformer per dataset: strict types, UTC, Pydantic checks counted not raised, then available_at, source_run_id, dataset_version.

    silver/base.py, silver/elexon/system_prices.py

  • Silver: typed Parquet, Hive-partitioned

    silver/{source}/{dataset}/year=YYYY/month=MM/; append-only datasets keep one file per capture, suffixed _run{capture time}.

    storage/paths.py, silver/base.py

  • Gold: a builder and SQL views

    Polars builder system_marginal_price; SQL views gold_uk_imbalance_context, gold_gb_day_ahead_benchmark, gold_eu_gas_storage.

    gold/system_marginal_price.py, gold/views/

  • DuckDB views over Parquet

    One view per dataset over read_parquet with Hive partitioning; append-only datasets also get a _latest view.

    storage/duckdb.py, silver/latest_views.py

  • One file: gridflow.duckdb

    Views over the Parquet, plus the pipeline_runs, pipeline_watermarks and quality_reports tables. No server.

    storage/duckdb.py

  • The gridflow command

    init, ingest, transform, build, pipeline, backfill, export-csv, status, quality, reset, prune.

    cli.py

  • GridflowClient, read-only, returns Polars

    from gridflow.serving.client import GridflowClient: query, get_system_prices, get_imbalance_context, get_gas_storage and more.

    serving/client.py

  • Notebooks

    Any notebook can open a GridflowClient; the gridflow_models workbench notebooks do, through their setup helper.

    gridflow_models/research/notebook_setup.py

  • gridflow_models, reading as of a time

    Training and backtests read silver Parquet directly, keeping only rows whose available_at is at or before the as-of time.

    gridflow_models/data/gridflow_source.py, Models page

How it stays correct

Raw bytes

Raw responses are kept, so any silver table can be rebuilt without calling the vendor again.

bronze/writer.py
Re-runs

Re-runs are safe: every file lands by temp file and atomic rename, never half-written.

storage/parquet.py
Validation

Rows that fail validation are still written, counted, and the run is marked completed with warnings.

silver/base.py
available_at

Each row gridflow writes carries available_at: vendor publication time if given, else a dated estimate or gridflow's clock.

silver/base.py
One file

One embedded DuckDB file is the catalogue; GridflowClient opens it read-only, and there is no server.

storage/duckdb.py
Run tracking

Every ingest, transform and build writes a row to pipeline_runs with its status, row counts and any error, and each silver row's source_run_id points back to it. Incremental ingest resumes from pipeline_watermarks. gridflow quality runs row-count, null-rate, gap and duplicate checks and writes them to quality_reports.

observability.py
quality/checks.py
CI

On every push and pull request, gridflow's CI checks the lockfile, runs ruff lint and format checks, mypy over src/gridflow, and pytest with live-API tests excluded.

.github/workflows/ci.yml
