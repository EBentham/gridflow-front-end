## Findings

1. **major** `page.family.members[0].differs` and `page.record.fields.dfs_procured_mw` / `dfs_provider_bids_accepted_total_cost_gbp`.
   - **What is wrong.** The summary line reads "Window totals for both seasons; accepted MW and cost sum the report's Accepted bids". That says the archive season's totals are sums of the report's Accepted bids. The report is tabled for the current season only (the report member line says so), so a reader who has silver cannot check that for the archive rows, and two lines on the same page pull in opposite directions. The two guide lines add "(checked)" with no scope and no checker. The rubric (section 1, last item) wants an equality either backed by a vendor or code rule or scoped to what the page shows. The vendor field text says only "Total volume of DFS accepted" and "Indicative total cost of accepted DFS bids"; the sum-of-report and x price x half an hour reading is the project's own measurement. That is the trap the seat named: nothing may imply the report covers the archive.
   - **Evidence.** The check holds for the 1,230 current windows in silver (above), and for the archive only against bronze with duplicates removed. The note body (`demand-flexibility.md` lines 558-559) says "the archive procurement components reconcile the same way", but the page never says the archive report is absent from silver in that sentence.
   - **Suggested fix.** "Window totals for both seasons; in the current season accepted MW and cost sum the report's Accepted bids". In the two guide lines, scope the check: "checked on the current windows" or "in the current file, summed over the report's Accepted bids (project check)". Keep "never add both".

2. **major** `page.what_it_is` (last sentence), `page.notebook.needs`, `page.chart_view.caption`.
   - **What is wrong.** The loss is not stated plainly. "Silver's summary key omits `event_id`, so a file with two events in one window fails to load" reads as a hypothetical. The writer's report says the page states "the newest NESO summary file fails to load"; the page does not. `notebook.needs` ("a capture of the summary and report files ingested") also reads as if a fresh ingest reproduces the notebook. It does not: a new capture of the summary file today fails the same way, and `query()` on the summary returns nothing.

   - **Suggested fix.** For example: "NESO's newest summary file puts two events in the same window, which silver's summary key (no `event_id`) cannot hold, so that file does not load and this page stops at the 6 October 2026 file." Add a half-line to `needs` saying the summary view is empty until that is fixed.
