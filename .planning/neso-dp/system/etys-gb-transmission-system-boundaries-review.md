## Findings

1. **major** `page.how_used[1]` (and the writer's report line "It claims no mapping"): "Locate boundaries that NESO's constraint reporting names, such as B6 and B7" tells a reader this file locates the boundaries in NESO's constraint reporting. The note says the opposite two lines away: "Whether these names match the codes in NESO's constraint tables (`SCOTEX`, `SSHARN`) is not stated by the vendor". What is measured is only that the file has records named `B6` and `B7`; the deck's `B6 (SCOTEX)` alias is in the thermal note, but nothing in this note's sources says the file's `B6` is the same boundary. Suggest: "Look up boundaries by name, such as B6 and B7, which NESO's constraint reporting also uses; NESO does not say the two are the same boundaries" (or drop the second bullet).
2. **major** Canonical note body, "Known issues and gotchas", first bullet: "Treat the geometry as opaque. No claim is made that the 34 features correspond one-to-one to named ETYS boundaries or that the shapes are geographically correct." The new measured bullet in "Catalogue facts" now says one feature is one named boundary drawn as a single line, which is that one-to-one claim (as a file structure fact, not a geographic one). The note contradicts itself. Reword the Known issues bullet to keep only what is still unclaimed, for example: "Treat the shapes as opaque: the names are one per feature (measured), but no claim is made that the lines are geographically correct or that they equal the boundaries in NESO's constraint tables." The Overview line "gridflow claims no geometry meaning" is still true and can stay.
3. **nit** `page.related[0].note` ("Daily costs at boundaries NESO's forum deck calls B6 and B7"): true and supported, but by the thermal note (Operational Transparency Forum slides of 24 June 2026, document 383631, "Transparency | Network Congestion" table, `B6 (SCOTEX)`, `B7 (SSHARN)`), not by this note's own sources. It can stay because it matches the approved thermal page; add the one-line citation to this note (Links or the Known issues bullet from finding 2) so the line is sourced where it is written. If finding 1 is fixed as suggested, this line and that one agree.
4. **nit** `page.what_it_is`, `page.summary`: the page says "as used in ETYS 2024" as fact in the summary and never mentions that the file is named `mar25` (visible only inside the download URL). The note's Known issues records the mismatch and says NESO does not explain it. Add one clause in `what_it_is`, for example: "NESO's resource title says 2024; the file itself is named mar25, and NESO does not say why." Also, "in NESO's words, 'name and geographical path data'" is taken from the package notes while "ETYS 2024" and "Interactive Webmap" come from the resource description; both are accurate, but "in NESO's words" can read as one quotation covering the whole sentence. Attributing the quoted phrase alone (it already is, by the quotation marks) is enough; the clause above would settle it.
