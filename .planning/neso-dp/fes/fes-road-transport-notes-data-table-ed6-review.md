## Findings

1. **Major. `what_it_is`, `facts.grain`, `record.fields.category`, `how_used[0..1]`, `related[0].note`: every row is said to be a note on "one of [an ED5 column's] values", which the note body's own measure contradicts.**
   - Page text: "Each row names an ED5 column (...), one of its values, and NESO's note on it"; category guide line "A value of that ED5 column, as NESO spells it"; related note "The road transport table whose columns and values these notes explain"; how_used "Check whether an ED5 value is peak (5pm to 6pm) or annual, by edition".
   - Evidence: NESO's own text does not name ED5 ("a file supporting those data tables"); "ED5" is the page's gloss. The body's Join to ED5 section says the join is not literal and keeps `TODO: verify` before treating ED6 as a key to ED5. I re-ran the label comparison against ED5 silver (labels only): rows with no same-edition ED5 label are 3 (2023: `# Vehicles - Hydrogen`, `# Vehicles`, `Reference data`), 4 (2024: those three plus `V2G Maximum Capacity available at Peak`), 2 (2025: `V2G ... available at Peak`, `# Vehicles - Hydrogen`) and 2 (2026, same two). Two of those are frame rows (`V2G Maximum Capacity available at Peak`, `# Vehicles`), so the guide's "a value of that ED5 column" is wrong for rows the reader is looking at. `Reference data` is a note about ED1 and V2G modelling, not an ED5 value. `how_used[1]` also offers a peak or annual check "by edition", but the 2023 and 2024 files have no `Annual` note at all (`# Vehicles` stands in).
   - Do not fix by stating counts (that is local data). Fix by wording: say each row gives an ED5 column name, a value and NESO's note, drop "one of its values" and "A value of that ED5 column" (use "A value NESO names under that column"), and give related[0] NESO's own relation, for example "The road transport table these notes support". For `how_used[1]` use something like "Read NESO's note on `Peak` and `Annual`, by edition".
2. **Nit. `record.fields.column_name`:** "NESO files hydrogen vehicles under `Fuel`" is easy to misread as the hydrogen fuel type, which is what a `Fuel` column normally holds. State the row: "NESO files the `# Vehicles - Hydrogen` count under `Fuel`". The row is not in the frame, so the guide is the only place the reader learns it.
3. **Nit. Plain English and precision.** "V2G" is first used in `how_used[2]` and the guide with no expansion on the page prose (the expansion sits only in the folded NESO text); "HGVs" is also unexpanded. Spell out "vehicle-to-grid (V2G)" at first use and "heavy goods vehicles". The `description` guide line says the 2025 V2G notes add "HGVs and buses parked at the depot"; the Maximum Capacity note says "depot charged", only the at-Peak note says "parked at the depot". Say "charged or parked at the depot". `facts.grain` uses "ED5" before `what_it_is` introduces it; the hero summary already says "the road transport table", so "per column and value of NESO's road transport table (ED5)" would do.
4. **Nit. Canonical note, "What changed between editions":** "the revisions beyond line breaks and full stops are:" reads as exhaustive. Silver also has: 2024 "including" to "includes" (`Electric Vehicle Peak Demand`), "is" to "would be" (`Electric Vehicle Unmanaged Peak Demand `), the `Reference data` typo "flexibilitly" to "flexibility", `# Cars - All` "a" to "A"; 2026 `Hybrid (Electricity & Petrol/Diesel)` "E.g." to "e.g.,". Say "the main revisions" (the writer's report says minor edits were left out; the body should too).
5. **Nit. `raw_feed.requests`:** the note says "one `package_show`, then each edition's CSV" but the four listed requests are the CSVs only. Sibling pages (ED4, resource adequacy, aggregated BSAD) list the `package_show` URL. The request count cap is 4, so adding it needs dropping one file as ED4 did ("Shown: 2023, 2025 and 2026"), or saying the `package_show` call is not shown.
6. **Nit. `related[1].note`** "FES electricity demand; the 2023 and 2024 notes keep reference data out": the NESO note says "Data is not used in the calculation of Peak/Annual/Minimum in ED1", which is narrower than "keep reference data out" of FES electricity demand. Reword to what NESO says, within 12 words.
7. **Nit. `record.fields.category`** says "trailing space kept", true for `Electric Vehicle Unmanaged Peak Demand ` in all four editions, but that row is not among the eight, so the reader cannot see it. Keep it only if a frame row shows it, or move it to the notebook lead.
