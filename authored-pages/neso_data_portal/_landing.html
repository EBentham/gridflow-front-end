NESO Data Portal.

The National Energy System Operator's general open-data catalogue — a CKAN file-download platform, distinct from the existing NESO Carbon Intensity API despite the shared name. Per-BMU wind availability forecasts, embedded (sub-transmission) wind/solar generation forecasts, and a half-hourly GB generation-mix archive back to 2009. The portal publishes 129 packages; 3 are implemented here, and the 29 listed below are the ones most readily added next.

Planned.

The portal publishes 129 packages in total. Thirty-three of them are straightforward to ingest — one CSV file each, no bespoke parser and no format changes part-way through their history. Two of those are already built: daily_wind_availability and historic_generation_mix, above. Two others describe the portal rather than the grid, so they are not treated as datasets here: data-portal-planned-changes-known-issues is the portal's own changelog, and national-demand-balancing-mechanism-units is a bare list of BM unit IDs with no time dimension. That leaves the 29 listed below — catalogued and understood, but not yet connected to a schema or ingested. The other 96 packages need more work per dataset: several files spanning different eras, or formats other than CSV such as spreadsheets, archives and PDFs.

Caveats · known quirks

What to watch for.

01

Gridflow downloads whole files here, it does not page rows

Every other gridflow vendor is a JSON or XML query API — send parameters, get rows back. On the Data Portal, package_show returns metadata, and the bulk data lives in CSV/XLSX/ZIP resources discovered through that metadata and downloaded separately. CKAN does expose row-level queries over these resources via datastore_search and datastore_search_sql, but at a much tighter 2 requests/minute; gridflow takes the whole-file download path instead, which is why this connector reads bytes rather than paging rows.

Source · vault README.md · endpoints.md
02

Two vendors share the "NESO" name

This page documents the Open Data Portal (CKAN, api.neso.energy). The separate NESO Carbon Intensity vendor on this site documents api.carbonintensity.org.uk, unrelated infrastructure with its own gridflow source key. The two are not merged and should not be confused.

Source · vault README.md
03

Keyless, but rate-limited by IP block, not HTTP 429

No API key is required for any of the 9 CKAN actions this portal exposes. NESO's own guidance recommends a maximum of 1 request/second on the action API and reserves the right to block the requesting IP if that guidance isn't followed — there is no documented soft-throttle response to detect and back off from.

Source · vault endpoints.md · README.md "Rate limits"
04

No backfill: the portal serves only its current file

All three implemented datasets refuse a historical gridflow backfill or a historical ingest window by design — verified live. daily_wind_availability and embedded_wind_solar_forecast are rolling forward-looking forecasts; historic_generation_mix republishes its whole 2009-to-now archive on every capture, so the vintage axis (not a historical query parameter) is how successive captures are told apart.
